# 两件事随之改变，而且都推翻了旧结论：
#
# 1) 配置基底改为【设备真实配置】reference/device-config.txt
#    它自带 SYSVIPC=y / POSIX_MQUEUE=y / IPC_NS=y / PID_NS=y / USER_NS=y，
#    所以这些项现在是"必须跟随设备"，不再是危险项（少开反而会崩）。
#    scripts/patch-abi-safe.sh（把 mq_bytes 挪进 KABI 保留槽）已停用 ——
#    本版 ROM 的 user_struct 就是官方布局，再挪反而改字段顺序 → 725 符号变。
#
# 2) ABI 基线重建：abi-baseline/abi-crcs.txt 由设备全部 390 个 .ko 生成，
#    4188 个符号（旧基线 1613 个，CRC 逐个相同，新基线是纯超集）。
#
# 本版新增的 Droidspaces v7 相关特性：
#   CONFIG_MACVLAN                   --net=macvlan
#   CONFIG_IP6_NF_NAT                IPv6 NAT
#   CONFIG_IP6_NF_TARGET_MASQUERADE  --net=nat 的 IPv6 出网
#   CONFIG_CFS_BANDWIDTH             --cpus
# 仍然拿不到的：
#   CONFIG_CGROUP_DEVICE / CGROUP_PIDS
#     → CGROUP_SUBSYS_COUNT 7→9 会撑大 struct css_set 的定长数组，
#       295 个符号 CRC 必变 → vendor 模块集体拒载 → 卡米标。
#       代价：Docker 的 devices 控制器告警、Droidspaces 的 --pids-limit 不可用。
#       要真正拿到只能连 vendor 模块一起重编重刷。
#
# 历史 bisect（针对 5.10.260 那版设备，仅供参考，不要照搬）：
#   control（设备原版配置）→ 绿 ｜ D2（无碎片）→ 绿 ｜ E2（+KSU）→ 绿
#   G（只 USER_NS）→ 绿 ｜ B（CGROUP_DEVICE+PIDS）→ 红 295
#   H（POSIX_MQUEUE+IPC_NS）→ 红 725（user_struct.mq_bytes）
