# 2026-10-24

## 设备 OTA 换内核 → 全链路重新钉定 + 按 Droidspaces v7 加特性

### 触发
用户贴了 Droidspaces v7.0.0 的检测结果：
- 已满足：PID/Mount/UTS/IPC ns、pivot_root、seccomp、cgroup v2、FUSE、TUN、OverlayFS…
- 缺 4 项：`CONFIG_MACVLAN`、`CONFIG_IP6_NF_NAT(+TARGET_MASQUERADE)`、
  `CONFIG_CFS_BANDWIDTH`、`CONFIG_CGROUP_PIDS`
- 用户说"内核更新到 24.0 了，我已经拉取分支"

### 实测发现（和用户说法不完全一致，以设备为准）
- `uname -r` = **`5.10.269-gki-gdafb11eb4fa2`**，系统仍是 **LineageOS 23.2**
  （`23.2-20261002-NIGHTLY-unicorn`），不是 24.0。→ 是 OTA 换了 nightly 的内核 commit。
- 也就是说：**我们之前编的 5.10.260 内核已被官方包覆盖**，chroot 里的 Docker 补丁
  还在（在 /data），但内核层的 namespace 配置回到了官方默认（虽然官方这版已开
  SYSVIPC/POSIX_MQUEUE/IPC_NS/PID_NS/USER_NS）。
- 活动槽从 `_a` 变回 `_b`。

### 重建了两样基线（换 ROM 必做）
1. `reference/device-config.txt` ← 设备 `/proc/config.gz`（7747 行）
2. `abi-baseline/abi-crcs.txt` ← 设备 **390 个** `/vendor_dlkm/lib/modules/*.ko`
   的 `__versions` 段 → **4188 个符号**（旧基线 1613，重合部分 CRC 逐个相同，纯超集）
   - 拉模块的办法：`su -c "tar -C /vendor_dlkm/lib/modules -cf /data/local/tmp/m.tar ."`
     再 `adb pull`（直接 `adb pull` 目录是 0 files，因为 adb shell 用户读不了 vendor_dlkm）
   - 数据居然一致：说明 ABI 在这两个版本之间没变（对 390 个模块覆盖的符号而言）

### 关键结论：旧的两条"铁律"过期了
- 本版设备配置 **`SYSVIPC=y`、`POSIX_MQUEUE=y`** ⇒
  - `SYSVIPC` 不再是危险项，**必须跟随设备开**（少开会让 task_struct 少
    sysvsem/sysvshm → 反而 ABI 崩）
  - `patch-abi-safe.sh`（把 mq_bytes 挪进 KABI 保留槽）**必须停用** ——
    那会改字段顺序，725 符号 CRC 变。CI 已加防呆检查，脚本标 DEPRECATED。
- `CGROUP_DEVICE` / `CGROUP_PIDS` **仍然不能开**（css_set 定长数组，295 符号）
  ⇒ Droidspaces 的 `--pids-limit` 继续拿不到。

### 架构性改动：配置基底换成「设备真实配置」
- 新脚本 `scripts/overlay-config.py`：把碎片精确覆盖到完整 `.config` 上（其余逐字保留）。
  不用 `merge_config.sh`（对完整 .config 作基座时行为不可控，`-y` 会把 `=m` 全改 y）。
- `preconfig-kernel.sh` 新增 `BASE_CONFIG_FILE` / `EXTRA_FRAGMENT` 两个环境变量。
- 本地验证：合并结果与设备配置**只差 5 项**，全是我们要加的
  （CFS_BANDWIDTH / IP6_NF_NAT / IP6_NF_TARGET_MASQUERADE / MACVLAN / KSU_TOOLKIT_SUPPORT）。
- 踩了个坑：第一版 parser 把 fragment 里"注释掉的建议项"（`# CONFIG_KSU_TRACEPOINT_HOOK=y`）
  当成有效配置写进 .config，把设备原本的 y 覆盖成 n。已修：只有 `# CONFIG_X is not set`
  算有效，其余 `#` 行一律忽略。

### 编译器
- 设备 `CONFIG_CC_VERSION_TEXT` = `Android (13290119, based on r547379) clang version 20.0.0`
  ⇒ 必须用 **clang-r547379**（之前用的 r563880c / clang 21 已不适用）。
- 依据：5.10 是**传统 CFI**（模块里有 `.cfi_jt` / `__cfi_check`，**没有** `__kcfi_typeid`），
  跨模块 type id 由编译器分配，版本不一致会卡米标。
- GitHub 上只有 `KiTTYsh/android_prebuilts_clang_host_linux-x86_clang-r547379`（约 872MB，**Git LFS**）。
  已在 `assemble-lineage-kernel.sh` 里加进镜像列表 + 自动 `git lfs pull`（判断 bin/clang <1MB 即指针）。
  googlesource archive 仍作兜底。
