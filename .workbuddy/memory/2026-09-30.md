### 核实到的关键事实（重要，后续复用）
1. `CONFIG_CGROUP_DEVICE` 在 android13-5.10 / 小米 SM8450 `gki_defconfig` 里**完全不存在**，
   Kconfig `bool "Device controller"` 无 `default y` → 默认 n。这是 Docker devices 缺失的根因。
2. `gki_defconfig` 里是 **`# CONFIG_PID_NS is not set`**（显式关闭），Docker 起容器必需 → 必须改本体。
3. `CONFIG_USER_NS` 在 5.10 是 **`default n`**，不写就是关。
   `CGROUP_PIDS` / `NF_TABLES` / `BRIDGE_NETFILTER` 同属"不写即关"。
   `NET_NS`/`UTS_NS`/`IPC_NS`/`SECCOMP` 是 `default y`，本来就开。
4. **defconfig 碎片有硬约束**：`build.config.msm.common` 的 `merge_defconfig_fragments()`
   检测到 `Previous value: CONFIG_X=[ym]` 就 `ERROR! Detected overridden config!` 退出；
   `check_merged_defconfig()` 要求最终 `.config` 与 defconfig 差异**全是新增行**。
   ⇒ 配置必须写 `gki_defconfig` **本体**，不能写 `vendor/*_GKI.config` 碎片。
   （唯一例外：要改 `CONFIG_LOCALVERSION` 必须改碎片，因为碎片里本就设了 `-gki`。）
5. **官方 MiCode 没有 unicorn 分支**（255 个分支中 u 段只有 uke-v-oss / ulysse-n-oss）。
   SM8450 只开源了 `zeus-s-oss`（小米 12/12 Pro，Android 12），
   `arch/arm64/configs/vendor/` 只有 cupid/zeus/waipio/neo 碎片。
6. 可用的源码路径：
   - 社区自洽 kernelplatform：`xiaomi-sm8450-kernel/manifest` @ `zeus-s-oss`（default.xml 内含
     msm-kernel + common + build + clang prebuilts + external/dtc + vendor/qcom/*），
     入口 `./build.sh zeus`，`MSM_ARCH=zeus`，输出 `out/msm-kernel-zeus/dist/`
   - LineageOS 路线：`LineageOS/android_device_xiaomi_unicorn` +
     `cupid-development/android_kernel_xiaomi_sm8450`（lineage-21 / 22.0~22.2，
     碎片 `arch/arm64/configs/vendor/unicorn_GKI.config`）
7. ReSukiSU `kernel/setup.sh` **不改 defconfig**（只 clone + 软链 drivers/kernelsu +
   改 drivers/Makefile&Kconfig）⇒ `CONFIG_KSU=y` 必须手写。
   5.10 GKI 默认 hook 是 **kprobes**（不是 tracepoint）；tracepoint 需显式
   `CONFIG_KSU_TRACEPOINT_HOOK=y`，二者不要同开。
8. 最大风险：碎片设 `CONFIG_LOCALVERSION="-gki"`，与 stock HyperOS 内核版本串不一致
   → stock `vendor_dlkm` 模块 vermagic 不匹配 → 能开机但 WiFi/BT/音频废。
   对策：刷同源 `vendor_dlkm.img`，或对齐 LOCALVERSION，或基于现有自定义内核源码改。
   好消息：本次新增的 cgroup/namespace 项都不在 KMI 符号表内，不破坏 ABI。

## 追加 3：SSH 到 192.168.0.10 + 编译方案时间评估（结论选 GitHub Actions）

### 关键事实
- 用户给的 `ssh root@192.168.0.10`（密码见用户提供，不入库）：
  **不是电脑，是手机上的 Ubuntu chroot**。证据：`/proc/version` = 设备的
  `5.10.260-gki-gef362912d37b`；CPU = Cortex-X2/A710/A510；`/dev/block/by-name/boot_{a,b}` 可见；
  根挂载 `/dev/block/loop41`。
- 该 chroot：Ubuntu 26.04、`nproc`=6、11.2GB 内存（可用 6.6GB）、4GB swap、
  loop 镜像 247GB 可用、**无 make/gcc/clang/dtc**（apt 有 clang 21.1.6）、
  **清华镜像通但 `curl https://github.com` 连上后传不动数据**。
- 本机 PC：AMD Ryzen 7 5800H 8C/16T、13.9GB 内存（**仅 3.4GB 空闲**）、
  C:127/D:113/E:47GB、`HypervisorPresent=True`。
- SSH 用的认证方式：password（root 允许），前期密码试错失败是因为密码不对，不是配置问题。
- **踩坑：PowerShell 工具的 stdout 在本会话取不到**（多次 exit 0 无输出）。
  绕过办法：让 PowerShell 把结果写进文件，再用 Read 读 —— 有效。

### 新发现的工具链事实（重要）
设备 `/proc/version` 暴露官方编译用的是 **clang 21.0.0 (r563880c)**，
而内核树 `build.config.common` 写的是 `CLANG_PREBUILT_BIN=...clang-r416183b/bin`。
原因是 LineageOS 用 `KERNEL_CLANG_VERSION := $(LLVM_AOSP_PREBUILTS_VERSION)`
（见 vendor/lineage/config/BoardConfigKernel.mk）覆盖了树里的声明；
且 LineageOS 对这类树是**直接跑 make**，不是 AOSP 的 build/build.sh。
- clang 版本**不影响 ABI**（MODVERSIONS 的 CRC 由 genksyms 从源码声明算，与编译器无关；
  vermagic 也不含编译器），只影响能否编过 → 工作流加了 `clang_version` 参数
  （默认 clang-r416183b，备选 clang-r563880）。
- `LineageOS/android_prebuilts_clang_kernel_linux-x86_clang-r563880` **不存在**（404），
  所以 assemble 脚本加了回退：从 android.googlesource.com 的
  `+archive/refs/heads/main/<ver>.tar.gz` 拉目录归档，并 sed 掉 `build/build.config.common`
  里的 `CLANG_PREBUILT_BIN`。

### 时间评估结论（写了 reference/build-time-evaluation.md）
- A 手机 chroot 本地编：**不可行**（8~12GB 源码从 GitHub 拉不动；ARM 弱；会让手机发烫）
- B PC + WSL2：2~4 小时（大头是下载；内存只剩 3.4GB 需 `.wslconfig` 限到 7GB）
- C **GitHub Actions：约 1~1.5 小时**（源码走机房内网 2~5 min，编译 40~70 min）
- 核心洞察：**瓶颈不是 CPU 而是那 8~12GB 源码**，Actions 把这段耗时消掉了。

## 追加 4：CI 实战三轮（run#1 attempt1/2 -> run#2），最终定位并修好构建方式

仓库：`TianXiao203/12sp`（public）。**我这边现在能直接 `git push`**：
`git -c url."ssh://git@github.com/".insteadOf="https://github.com/" push origin main`
（用户配了 SSH key，沙箱允许 22 端口；HTTPS 走代理会 502）。
**日志读不到**：Actions logs / artifacts API 需要 admin（403），check-runs annotations 为空。
所以只能靠"用户贴日志"或"把诊断信息塞进 artifact"。

### run#1（sha 71372f8）
- attempt1 死在步骤3（清盘/swap），后面全 skip。原因该步有 `set -e` 且 `swapon` 可能被 runner 拒绝。
- 用户点的是 **Re-run**，它固定重跑原始 commit —— **不会拉新代码**（重要坑：要改代码必须 Run workflow）。
- 修：该步全容错；`build/` 备用源修正（`aosp-mirror/kernel_build` 是 404，
  改用 `xiaomi-sm8450-kernel/android_kernel_platform_build`，已验证含 build.sh / build-tools(path+sysroot) / android / envsetup.sh）；
  `KERNEL_DIR` 必须相对（`build.sh` 会 `cd ${ROOT_DIR}/${KERNEL_DIR}`，绝对路径拼坏）。

### run#2（sha 1cacd17）
- 步骤 3/4/5/6/8/10 全过；**步骤11「编译内核」0 秒却 success，步骤12 failure**。
- 定位：`build/build.sh` 在 1~2 秒内退出，而 `build.sh 2>&1 | tee log` **没有 pipefail**，
  退出码被 tee 吞掉 -> 显示"0 秒成功"；步骤12 因 `$WS/out` 不存在而立刻 exit 1。
- `build.sh`（= `build.config.msm.common` 的 `merge_defconfig_fragments`）有两处快速 `exit 1`：
  `ERROR! Detected overridden config!` 和 `ERROR! Treating config warnings as errors`。
- **顺带发现正确性 bug**：走 build.sh 只会合并 `vendor/waipio_GKI.config`，
  而 LineageOS 官方 `TARGET_KERNEL_CONFIG` 是 5 件套
  （gki_defconfig + vendor/{waipio,xiaomi,unicorn}_GKI.config + vendor/debugfs.config）
  -> 会丢掉 MI_CHARGER_M81 / MI_THERMAL_MULTI_CHARGE 等设备专属配置。

### 最终方案（commit 3caf778，已推送）
新增 `scripts/preconfig-kernel.sh`：
1. 自己用 `merge_config.sh -m -r -y` 合并完整 5 件套（不动 build.sh 的严格校验）
2. 用 `scripts/config` 把 LTO 从 **FULL 改成 THIN**
   （设备实测 `CONFIG_LTO_CLANG_FULL=y` 来自 gki_defconfig:97；16GB runner 跑 FULL LTO 会 OOM）
3. 自检 5 个关键项（CGROUP_DEVICE/PID_NS/USER_NS/SYSVIPC/KSU）必须 =y
然后 workflow 直接 `make O=$OUT ARCH=arm64 LLVM=1 LLVM_IAS=1 Image -j`（= LineageOS kernel.mk 的做法），
全程 `set -eo pipefail`。只编 Image，不编 modules/dtbs/vendor_dlkm。
`校验 .config` / `核对 release` 改为 `continue-on-error`；诊断日志 `if: always()` 上传含 build.log。

### 环境/工具坑（复用价值高）
- **PowerShell 工具的 stdout 在本会话取不到**（多次 exit 0 无输出）→ 让它写文件再用 Read 读。
- **Git Bash 的 `/tmp` 与原生 Windows Python 的 `/tmp` 不是同一个路径**
  → 给 Python 传数据要用 stdin（`cat f | python -c ...`），别 `python -c "open('/tmp/f')"`。
- 本环境 `grep -c $'\r'` 判断 CRLF **会误报**（返回行数而非 0）→ 用 Python 按字节数统计才准。
- 沙箱偶发返回 `sandbox-center cmd decisionRecord missing actual resource subject`，重试即可。
- 设备内核里的 clang 版本可白捡：`/proc/version` 里写着
  `Android (... based on r563880c) clang version 21.0.0`，而树里 `build.config.common` 写的是 r416183b
  （LineageOS 用 `KERNEL_CLANG_VERSION := $(LLVM_AOSP_PREBUILTS_VERSION)` 覆盖）。
  clang 版本不影响 ABI（CRC 由 genksyms 从源码声明算、vermagic 不含编译器），只影响能否编过。
