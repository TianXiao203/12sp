## Run#4 第 18 步 1 秒失败的真凶：.gitignore 的大小写陷阱
`git check-ignore -v anykernel3/anykernel.sh` 输出：
```
.gitignore:6:AnyKernel3/    anykernel3/anykernel.sh
```
本机 `core.ignorecase=true`（Windows git 默认），**gitignore 匹配也不区分大小写**，
所以当初为忽略上游克隆目录写的 `AnyKernel3/` 把仓库里真正要用的 `anykernel3/`
整个忽略了 → `anykernel3/anykernel.sh` **从未入库** → runner 上
`cp "$HERE/anykernel3/anykernel.sh"` 找不到源文件，配合 `set -e` 静默秒退。
这解释了全部现象：1 秒、无任何自定义报错、第 19 步被跳过。
修复：.gitignore 删掉该模式；该文件已入库。
**教训：Windows 上写 .gitignore 一定要 `git check-ignore -v` 逐个验证，
尤其注意大小写只差的名字。**

## 第二个必须修的问题：版本串会带 `-dirty`
`scripts/setlocalversion`（lineage-23.2）关键两段：
- 第 110~121 行：工作树有未提交改动就追加 `-dirty`
- 第 56~59 行：**只要存在 `.scmversion` 就直接 `cat` 并 `return`**（跳过 dirty 判断）
- 第 100 行：sha 固定截 `cut -c1-12`

我们必然要改 `gki_defconfig` / `drivers/Makefile` / `drivers/Kconfig`，
所以不加处理会得到 `5.10.260-gki-gef362912d37b-dirty`
→ vermagic 不一致 → ROM 现成的 vendor 模块全部加载失败（能开机但 Wi-Fi/蓝牙/音频废）。
修复：在 assemble 里【刚 checkout、树还干净时】写
`$WS/common/.scmversion` = `-g$(git rev-parse HEAD | cut -c1-12)`
→ 版本串 = `5.10.260` + `-gki`(CONFIG_LOCALVERSION) + `-gef362912d37b`
= **`5.10.260-gki-gef362912d37b`**，与设备完全一致，且不受 dirty / git 版本 / core.abbrev 影响。

## Run#3（Actions）失败定位与修复 —— 提交 b63cd40

### 现象
Run#3（sha 3caf778）第 3 步（清盘/swap）过了、第 4~10 步全过（含组装 78s、集成 KSU），
但**第 11 步「预生成合并 defconfig」7 秒失败**，第 12 步起全部 skipped。

### 根因（已确诊）
`scripts/preconfig-kernel.sh` 里写了：
```
./scripts/config --file "$OUT/.config" ... -e THINLTO
```
但**本内核树里根本没有 `CONFIG_THINLTO` 这个符号** —— 只有 choice 成员
`LTO_CLANG_THIN` / `LTO_CLANG_FULL`（用设备真实 .config 第 773~781 行证实）。
对未知符号执行 `scripts/config -e` 会退出非零，脚本是 `set -euo pipefail` → 整步失败。

### 顺带查实的三条内核事实（都是源码原文）
1. `arch/arm64/configs/gki_defconfig` 无 `CONFIG_CGROUP_DEVICE` 行 → 默认 n（Docker WARN 的来源）。
2. `# CONFIG_PID_NS is not set` 是硬编码关闭；`CONFIG_USER_NS` 在 5.10 是 `default n`。
3. 顶层 Makefile（lineage-23.2，5.10.260）：
   - `422: KCONFIG_CONFIG ?= .config`（**相对路径**）+ `423: export KCONFIG_CONFIG`
     → 配合 `O=` 时 `.config` 落点有歧义，必须导出绝对路径。
   - `435: ifneq ($(LLVM),)` → **支持 `LLVM=1`**。
   - `581-591 outputmakefile`：O= 构建前检查 `$(srctree)/.config`、`$(srctree)/include/config`、
     `$(srctree)/arch/$(SRCARCH)/include/generated` 是否存在，任一存在就报
     `*** The source tree is not clean, please run 'make mrproper'`。

### 修复内容（b63cd40）
- `preconfig-kernel.sh` 重写：不再用 `scripts/config`；thin LTO 改为生成
  **最后一个碎片** `vendor/zz-docker-thinlto.config` 交给 `merge_config.sh` 去重覆盖
  （实测 `LTO_CLANG_THIN=y` / `# CONFIG_LTO_CLANG_FULL is not set` ✓）。
